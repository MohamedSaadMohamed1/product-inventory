# Product Inventory & Stock Reservation API

A production-ready RESTful API built in Go for managing product catalogs and handling order placements with atomic stock reservation and concurrency safety.

## Architecture

We use a **Clean-ish Architecture** consisting of decoupled layers:

```
                    ┌──────────────┐
                    │    Client    │
                    └──────┬───────┘
                           │ HTTP (with Rate Limiting & JWT Auth)
                           ▼
                 ┌──────────────────┐
                 │    HTTP Handler   │ (internal/product/handler.go, internal/order/handler.go, internal/auth/handler.go)
                 │  Request/Response │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │     Service      │ (internal/product/service.go, internal/order/service.go, internal/auth/service.go)
                 │  Business Logic  │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │    Repository    │ (internal/database/db/ - generated by SQLC)
                 │   Database Access│
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │    PostgreSQL    │ (ACID Transaction isolation with SELECT FOR UPDATE row-locks)
                 └──────────────────┘
```

---

## Technical Features

1. **Atomic Concurrency Control**: Uses database row-locking (`SELECT FOR UPDATE`) on product rows.
2. **Deadlock Prevention**: Product IDs are sorted in ascending order before querying, ensuring all concurrent transactions lock resources in the exact same sequence.
3. **Database Guardrails**: An explicit check constraint `CONSTRAINT chk_stock_quantity_non_negative CHECK (stock_quantity >= 0)` ensures no concurrency race ever causes negative stock.
4. **Bcrypt Password Hashing**: Passwords are securely hashed and matched.
5. **JWT Authentication & RBAC**: Requests are authenticated via standard JSON Web Tokens. Access control is enforced (Admins can perform product write operations; Customers are restricted to viewing catalog and managing their own orders/profile).
6. **Token Bucket Rate Limiting**: In-memory IP-based rate limiter (10 requests/second per IP, burst capacity of 20) protecting endpoints from scraping and DDoS attacks. Includes a background cleanup goroutine to avoid memory leaks.
7. **Pagination**: Core list endpoints (Products & Orders) are paginated using `page` and `limit` query parameters with SQL `LIMIT` and `OFFSET`.
8. **Structured Swagger Documentation**: Interactive API specs available at `/swagger` categorized by functional domains (Authentication, Products, Orders).
9. **Database Backup & Restoration Tools**: Scripts provided in `scripts/` to back up database data dynamically.

## Prerequisites & Installation

To run this application locally, you must install the following prerequisites on your host machine:

### 1. Go (Golang) Compiler
* **Required Version**: Go 1.23 or newer (Go 1.26 recommended).
* **Download**: [Official Go Downloads](https://go.dev/dl/).
* **Verification**: Verify Go is installed and in your PATH by running:
  ```bash
  go version
  ```

### 2. PostgreSQL Database Server
* **Required Version**: PostgreSQL 14 or newer.
* **Download**: [Official PostgreSQL Downloads](https://www.postgresql.org/download/).
* **Installation Tip (Windows)**: During the installation wizard, set the default password for the `postgres` user (e.g., `postgres`) and use the default port `5432`. Make sure the database service is started.
* **PATH Setup (Windows)**: To run commands like `psql` or `pg_dump` from your terminal, add the PostgreSQL binary folder to your system environment variables PATH (default location: `C:\Program Files\PostgreSQL\<version>\bin`).

### 3. Git (Version Control)
* **Download**: [Official Git Downloads](https://git-scm.com/downloads).
* **Verification**: Verify Git is installed by running:
  ```bash
  git version
  ```

### 4. Make Utility (Optional)
* **Windows**: You can install GNU Make via winget if you wish to use Makefile shortcuts:
  ```powershell
  winget install GnuWin32.Make
  ```
  *(Otherwise, you can run Go commands directly as described in the steps below).*

## Configuration

### Step 1: Environment Variables
Create a `.env` file in the project root:
```bash
cp .env.example .env
```
Ensure your configuration variables are set correctly:
```env
DB_SOURCE=postgresql://postgres:postgres@localhost:5432/inventory_db?sslmode=disable
PORT=8080
ENV=development
JWT_SECRET=super-secret-token-key-change-in-production
```

### Step 2: Database Setup & Seed
1. Create the database `inventory_db`:
   ```sql
   CREATE DATABASE inventory_db;
   ```
2. Restore the database schema and seed data containing pre-hashed passwords:
   - **Windows (PowerShell)**:
     ```powershell
     .\make db-restore
     ```
   - **Linux/macOS (Bash)**:
     ```bash
     make db-restore
     ```
   *Note: Seed users loaded:*
   - **Admin**: Email: `admin@example.com` (Password: `adminpassword`) or `mohamed@example.com` (Password: `mohamedpassword`)
   - **Customer**: Email: `customer@example.com` (Password: `customerpassword`) or `saad@example.com` (Password: `saadpassword`)

### Step 3: Run the Application
Run the API locally using our wrapper command:
- **Windows (PowerShell)**:
  ```powershell
  .\make run
  ```
- **Linux/macOS (Bash)**:
  ```bash
  make run
  ```
The API will run on http://localhost:8080. The interactive UI dashboard is served at http://localhost:8080/.

## API Endpoints

### 1. Authentication

#### Register Account
- **URL**: `POST /api/v1/auth/register`
- **Request Body**:
```json
{
  "email": "newuser@example.com",
  "password": "mypassword",
  "role": "customer"
}
```

#### Authenticate & Login
- **URL**: `POST /api/v1/auth/login`
- **Request Body**:
```json
{
  "email": "customer@example.com",
  "password": "customerpassword"
}
```
- **Response** (`200 OK`):
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "email": "customer@example.com",
  "role": "customer"
}
```

---

### 2. Products Catalog

#### Create Product (Admin Only)
- **URL**: `POST /api/v1/products`
- **Headers**: `Authorization: Bearer <token>`
- **Request Body**:
```json
{
  "name": "Sony PlayStation 5 Pro",
  "description": "2TB SSD Console",
  "price": 69900,
  "stock_quantity": 10
}
```

#### List Products (Paginated & Public)
- **URL**: `GET /api/v1/products?page=1&limit=20`

#### Get Product Details
- **URL**: `GET /api/v1/products/{id}`

#### Update Product (Admin Only)
- **URL**: `PUT /api/v1/products/{id}`
- **Headers**: `Authorization: Bearer <token>`

#### Delete Product (Admin Only)
- **URL**: `DELETE /api/v1/products/{id}`
- **Headers**: `Authorization: Bearer <token>`

---

### 3. Orders

#### Create Order (Stock Reservation)
- **URL**: `POST /api/v1/orders`
- **Headers**: `Authorization: Bearer <token>`
- **Request Body**:
```json
{
  "items": [
    {
      "product_id": 1,
      "quantity": 2
    }
  ]
}
```

#### List User Orders (Paginated)
- **URL**: `GET /api/v1/orders?page=1&limit=10`
- **Headers**: `Authorization: Bearer <token>`
- **Response**: Returns a paginated list of orders placed by the current authenticated user.

#### Cancel Order (Stock Restoration)
- **URL**: `POST /api/v1/orders/{id}/cancel`
- **Headers**: `Authorization: Bearer <token>`
- **Response** (`200 OK`):
```json
{
  "message": "Order cancelled successfully"
}
```

#### Delete Order (Safeguarded)
- **URL**: `DELETE /api/v1/orders/{id}`
- **Headers**: `Authorization: Bearer <token>`
- **Response** (`204 No Content`):
  *Note: Deleting a pending order automatically restores its stock back to inventory.*

### Concurrency & Race Tests
The concurrency test inside `internal/order/concurrency_test.go` verifies correct behaviour under load:
1. It seeds a product with a stock of **10**.
2. Spawns **100 concurrent requests** ordering **1** quantity each.
3. Asserts that exactly **10 orders succeed**, **90 fail** with an `INSUFFICIENT_STOCK` error, and the final stock is exactly **0** (no negative stock).
4. Spawns **10 concurrent cancellation requests** on the same order, asserting that only the first cancellation succeeds and stock is restored by exactly **1** (no double-release).
5. Validates pagination logic.
